# Phase 2B.3 — Fineco decision workspace

This increment adds a **separate Streamlit section** to the existing
`Market-Intelligence-Operations-Console`, without a new model, brokerage
connection or independent application. Access it from the sidebar:
**Fineco · Piano operativo**.

## What is (and is not) available

- Existing multi-asset technical research remains the data source, using the
  **last completed run** and the **full** 3m/12m model tables, not just the
  globally ranked Top 10.
- Sector ETFs such as XLV/XLP and oil/broad commodities USO/DBC are contextual
  research inputs; they **do not** become suggested Fineco purchases.
- Three instruments are explicitly permitted for new capital planning:
  `VALL` (ISIN IE000VAHT5T0, Vanguard FTSE Global All-Cap UCITS ETF),
  `PRAB` (ISIN LU2233156582, Amundi Prime Euro Government 0–1Y UCITS ETF),
  and `SGLN` (ISIN IE00B4ND3602, iShares Physical Gold ETC, **not a UCITS
  fund**). All must be checked in the user's Fineco ticket before execution.
- Existing seven holdings are present as **empty input labels**, not hardcoded
  personal balances: VALL, PRAB, Core EUR government bonds, LifeStrategy
  60/40, Vanguard short US Treasury, metals producers, humanoid robotics.
  SGLN is a new eighth line only if purchased.
- No direct prices/units are computed for Fineco because the public market
  dataset chiefly contains US-listed proxies. **US-listed ETF scores do not
  prove an exact UCITS counterpart's return in EUR.**

## User input and privacy

The UI has `cash_eur`, confirmation of cash already credited, editable
position market values (EUR), and confirmation that **all** holdings have
been checked. Default is **zero investible cash**: monthly 1,000 EUR salary
savings are only counted after the user confirms the actual transfer.

Data is held in the visitor's Streamlit session, not saved in the GitHub
repository, public JSON export, SQLite database or a shared Streamlit cache.
Browser/session/server restarts may erase inputs. This is deliberate: a public
Streamlit Community Cloud app cannot provide a durable private broker portfolio
without authentication and protected storage.

## Translating signals to a limited portfolio

The pure function `src.intelligence.fineco_planner.build_fineco_plan`
encapsulates the policy (unit tests cover caps, failures and budget).

- `VT`/`ACWI` full-universe 12m/3m research evidence -> **VALL**
  tranche size, never automatic BUY. If strong on both horizons, a
  suggested 45% of investible cash; partial/weak evidence 20%; missing
  evidence 0%. This is a policy heuristic, not a calibrated expected return.
- Short EUR government **PRAB** -> 35% of cash, subject to existing holdings
  cap and manual broker checks; `BIL`/`SHY` USD government, `BKLN`
  floating-rate credit are *not* equivalent signals for the EUR product.
- `GLD`/`IAU` 3m trend evidence -> **SGLN** (up to 10% if both support;
  otherwise 0%). USD gold proxies are not a EUR-hedged gold forecast.
  Miner equity already held is not direct physical gold.
- `USO`/`DBC` and `XLV`/`XLP` -> macro/rotation notes only, no
  additional sector instruments.
- If the estimated allocation is below **150 EUR**, consolidate it into
  cash instead of suggesting a tiny order. Fineco actual commission plan,
  quotes, ETF Replay terms, whole-share sizes and spread must be checked.
- No increases above a provisional 45% effective equity, 40% short EUR
  sovereign or 10% physical gold share of the intended total portfolio.
  LifeStrategy 60/40 contributes 60% of its value to the effective equity
  approximation; this simplification can diverge from actual exposure.
- No sells are generated by a dashboard score, and no new funding for
  eToro is contemplated.

## Safety / go-no-go checks

1. Must have a completed run no older than 72h, never from the future.
2. Must have >=70% `price_status=VALID` in the public model.
3. Each accepted research proxy must be `VALID`, proper
   `technical-priority-v1`, with finite scores and a known research-only
   state. Missing evidence is `MISSING`, never treated as 50/neutral.
4. Cash and entire Fineco position input must be manually confirmed.
5. Zero/unconfirmed cash or missing/stale data yields **zero suggested
   acquisitions**. Missing asset-specific proxies yield no increases in
   the relevant risk sleeve, although PRAB's *structural* allocation is
   a policy choice, not a backtest or a model signal.
6. Even a populated proposal says **VALUTARE ACQUISTO** and has no action
   buttons for sending orders, changing positions or scheduling payments.
   It is not investment advice, an expected return forecast or a tradeable
   order ticket.
